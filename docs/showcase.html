03 · EVIDENCE TRACE

证据长什么样What evidence looks like

每条 insight 必须提供 evidence[]：来源 note id + 日期 + 原文摘录。以「观点演化」为例： Each insight must provide evidence[]: source note id + date + verbatim quote. Example from "Evolution":

「我总想先搭好完整的平台，再开始验证真正的需求。」N-014 · 2023-04-18
「把一次性交付拆成可复用链路，反而更快。」N-026 · 2023-09-02
「让机器持续发现，让人负责确认和承诺。」N-089 · 2025-03-08

在 Demo 里点开洞察卡，证据可跳回对应笔记——结论不悬空。 In the demo, insights link back to their notes — no floating conclusions.

诚实边界Honest boundary

页面中的全部笔记与洞察均明确标记为 Synthetic Demo Vault——不是真实用户数据，也不暗示当前已有真实模型结果。 All notes and insights are explicitly marked Synthetic Demo Vault — no real user data, no implied real-model results.

这是产品展示层，不修改任何 Notes Insight 插件核心逻辑。 A presentation layer only — the plugin's core logic is untouched.

设计约束：蓝色为唯一强调色；卡片与证据链优先、减少装饰性 UI；支持 light/dark，默认跟随系统。 Design constraints: blue as the only accent; cards and evidence chains over decoration; light/dark following system.
04 · INTEGRATE

接入真实数据：边界清晰Plugging in real data — clean boundaries

RULE 1

插件核心负责采集、检索、排序、生成结构化 insight；页面只消费一个经过校验的 JSON，不直接读 Vault。The plugin core collects, ranks and emits structured insights; the page consumes one validated JSON — never the raw vault.

RULE 2

每条 insight 必须带 evidence[]（note id + 日期 + 原文摘录），保证可审计。Every insight carries evidence[] (note id + date + quote) for auditability.

RULE 3

真实用户数据要加鉴权、脱敏与明确的 consent boundary。Real user data requires auth, redaction and an explicit consent boundary.

RULE 4

把 src/data/demoData.js 换成 API adapter（如 insightApi.js），别把请求逻辑塞进展示组件。Swap demoData.js for an API adapter (insightApi.js) — don't wire requests into view components.

05 · FAQ

常见问题 · 四问速览FAQ · The four questions

Q.1解决什么问题？What problem does it solve?＋
笔记工具都擅长「存」，没人在「回看」时帮你发现：观点怎么变的、什么问题一直没消失、哪些项目暗中相连。Notes Insight 把回看变成主动发现。Note tools store; none notice for you on revisit — how views shifted, which questions never died, which projects secretly connect. Notes Insight makes revisit active.
Q.2什么场景用？得到什么结果？Scenario and outcome?＋
产品详情页 + 可交互 demo：投资人/用户 30 秒看懂产品主张，每条洞察点开就有证据链。内容团队另有 CONTENT_PRODUCTION_PACK.md（视频脚本、分镜、素材清单）。A product page + interactive demo: 30 seconds to get the thesis, evidence one click away. Content teams get CONTENT_PRODUCTION_PACK.md (scripts, storyboard, assets).
Q.3内部是什么结构？How is it structured?＋
Vite + React，三件套：main.jsx（页面组装与交互）、styles.css（明暗主题 + 响应式）、data/demoData.js（合成笔记 + 洞察输出：6 笔记 / 4 洞察 / 8 Lens）。替换 demoData 即接真实数据。Vite + React, three files: main.jsx (composition), styles.css (themes), data/demoData.js (synthetic notes + insights: 6 notes / 4 insights / 8 lenses). Swap demoData to go real.
Q.4能复用什么？What can you reuse?＋
